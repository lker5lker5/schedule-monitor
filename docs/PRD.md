## 1. 背景与目标

项目团队需要随时看到《深地科学与人工智能中试基地建设任务分解表》的整体进度。现有载体是 Excel，存在三个问题：

1. 只能看到任务清单，看不到时间跨度与并行关系；
2. 进度更新后需要重新分发文件，团队不一定拿到最新版；
3. 阶段、责任部门、逾期风险需要人工比对。

目标是做一个**网页版甘特进度看板**：

- 团队成员打开网页即可看到整体进度、阶段、责任部门、逾期情况；
- 只有一名管理员，可登录后及时调整进度、增删任务；
- 页面尽量纯静态，不需要启动服务；
- 数据从 Excel 读取，替换 Excel 即可复用于其他项目。

## 2. 用户与权限

| 角色 | 权限 | 登录 |
| --- | --- | --- |
| 团队成员（默认） | 查看、筛选、缩放、查看任务详情、打印 | 不需要 |
| 管理员（单人） | 查看 + 编辑任务、调整阶段、导入/导出 Excel、发布数据 | 隐藏入口 + 口令 |

**安全边界（必须明确）**：

- 纯静态页面没有真正的服务端鉴权。口令只以 SHA-256 哈希形式存在于 `config.js`，能防止误入和普通成员误操作，**不能防止懂技术的人绕过**。
- 真正的控制点是"谁有权替换线上 `data.js` / 谁持有 GitHub 发布令牌"。
- 公网部署时，任何拿到链接的人都能看到全部内容；页面使用不可猜路径、`noindex`、`robots.txt` 降低被检索概率，但这些都不是访问控制。

## 4. 数据模型

数据文件为 `data.js`，通过普通 `<script>` 引入，内容形如：

```js
window.PROJECT_DATA = {
  meta: {
    projectId: "deep-earth-ai-pilot",
    title: "深地科学与人工智能中试基地建设任务分解表",
    logo: "assets/logo.jpg",
    updatedAt: "2026-11-20T23:50:00+08:00",
    version: 1,
    publishNote: "初始导入",
    phaseOrder: ["项目管理流程", "基础环境建设", "主体功能建设", "制度建设", "未分类"]
  },
  tasks: [
    {
      id: "t_2",
      seq: 1,
      name: "基地建设团队确定",
      departments: ["科教处"],
      start: "2026-11-06",
      end: "2026-11-06",
      progress: 100,
      phase: "项目管理流程",
      note: ""
    }
  ]
};
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `meta.title` | string | 页面主标题 |
| `meta.logo` | string | logo 相对路径，可为空 |
| `meta.updatedAt` | ISO string | 最近一次发布时间 |
| `meta.version` | number | 发布版本号，每次发布 +1 |
| `meta.publishNote` | string | 本次发布说明，可为空 |
| `meta.phaseOrder` | string[] | 阶段显示顺序；未列出的阶段排在后面 |
| `task.id` | string | 内部唯一 ID，不随序号变化 |
| `task.seq` | number | 显示序号，可重复但不建议 |
| `task.name` | string | 工作任务 |
| `task.departments` | string[] | 责任部门，由 Excel 中按 `、，,；;` 拆分 |
| `task.start` / `task.end` | `YYYY-MM-DD` | 计划起止日期（含首尾） |
| `task.progress` | number | 0–100 整数 |
| `task.phase` | string | 阶段；空值归入"未分类" |
| `task.note` | string | 备注，可为空 |

### 4.1 Excel 模板

标准模板为 8 列：

```
序号 | 工作任务 | 责任部门 | 启动时间 | 完成时间 | 进度（%） | 阶段 | 备注
```

兼容规则：

- 备注列可缺失（当前源表为 7 列）；
- 若没有"阶段"列但有"备注"列，则把备注内容当作阶段（兼容旧模板）；
- 列顺序不固定，按表头名称识别；
- 无法识别表头时，退回按 A–H 的位置解析，并在导入报告中提示。

## 5. 状态与指标规则

### 5.1 任务状态

| 进度 | 状态 |
| --- | --- |
| `0` | 未开始 |
| `1–99` | 进行中 |
| `100` | 已完成 |

### 5.2 风险标记

- **逾期**：`今天 > 完成时间` 且 `进度 < 100`。显示"逾期 N 天"，红色描边。
- **应启动未启动**：`进度 = 0` 且 `今天 > 启动时间` 且 `今天 <= 完成时间`。黄色提示。
- 已过完成时间但进度 100 的任务不标记逾期（系统没有实际完成日期，无法区分按期/逾期完成）。
- 逾期优先于"应启动未启动"，两者不重复计数。

### 5.3 统计口径

- **整体完成率** = 所有任务进度的算术平均（每条任务等权），四舍五入到整数。
- 阶段完成率 = 该阶段任务的进度平均。
- 任务状态计数：未开始 / 进行中 / 已完成 / 逾期 / 应启动未启动。
- 时间进度 = 已过天数 ÷ 计划总天数（今天早于最早启动为 0%，晚于最晚完成为 100%）。
- KPI 始终基于全部任务，不受筛选影响；筛选结果数量在工具栏单独显示。

## 7. 阅读端功能

### 7.1 页头

- 左侧：logo（白色圆角底托）+ 主标题。
- 右侧：`数据更新于 YYYY-MM-DD HH:mm`。
- 不显示副标题、不显示单位名称。
- 隐藏入口：
  - URL 带 `?admin=1` 时显示一个不显眼的"管理"按钮；
  - 连续点击 logo/标题 5 次也会打开登录框。

### 7.2 KPI

1. **整体完成率**：大号百分比 + 进度条 + "按 N 项任务进度平均"。
2. **任务状态**：堆叠条 + 未开始/进行中/已完成计数。
3. **风险提示**：逾期数（红）、应启动未启动数（黄）。
4. **计划周期**：起止日期、已过/总天数、时间进度。

### 7.3 甘特视图

- 默认按阶段分组；阶段顺序取 `meta.phaseOrder`，未列出的阶段按首次出现顺序追加，"未分类"最后。
- 阶段内按启动时间升序，同日按序号升序。
- 可切换"按序号平铺"，平铺时按序号升序。
- 阶段可折叠，折叠状态保存在本机。
- 阶段头显示：阶段名、任务数、平均进度、最早启动–最晚完成、逾期数；时间轴上显示一条阶段汇总条。
- 时间轴：
  - 日 / 周 / 月三档，默认周；
  - 范围自动覆盖最早启动到最晚完成，前后各留一周，按周一/周日对齐；
  - 顶部月份（日/周视图）或年份（月视图）分组；
  - 周末浅灰底色、月份分隔线；
  - 今天线 + "今天"标签。
- 任务条：
  - 按阶段配色；
  - 进度填充；
  - 未开始：浅色轨道 + 阶段色描边；
  - 进行中：部分填充；
  - 已完成：实心 + 勾；
  - 逾期：红色描边 + "逾期 N 天"徽标；
  - 应启动未启动：黄色虚线描边；
  - 单日任务显示为里程碑菱形；
  - 悬停显示浮动提示，点击打开详情。
- 左侧任务列固定，横向滚动时保持可见；表头固定。
- 任务行显示：序号、任务名 + 起止日期、责任部门、进度百分比 + 迷你进度条。

### 7.4 卡片视图

- 按阶段分组，每组一张卡片网格。
- 卡片内容：阶段色点、状态徽标、任务名、责任部门、起止日期、进度条、逾期/剩余天数。
- 桌面默认甘特，窗口宽度 < 768px 默认卡片；用户可手动切换，选择记入 URL。
- 手机端筛选、缩放等控件收纳为底部抽屉或横向滚动。

### 7.5 筛选与 URL

- 责任部门多选（按部门首次出现顺序排列）。
- 状态多选：未开始 / 进行中 / 已完成 / 逾期 / 应启动未启动。
- 关键词搜索：任务名、部门、阶段、备注。
- 筛选条件写入 URL 查询参数：`dept`、`status`、`q`、`view`、`zoom`、`group`。
- 支持"清除全部"和单项移除。
- 无结果时显示空状态。

### 7.6 任务详情

- 桌面右侧抽屉，手机全屏底部抽屉。
- 展示：任务名、状态、阶段、责任部门、起止日期、计划工期、剩余/逾期天数、进度环、备注。
- 管理员在此处可直接进入编辑。

### 7.7 打印

- 打印按钮：自动切换到月视图、展开全部阶段、切到甘特视图，然后调用浏览器打印，打印后恢复原状态。
- 打印样式隐藏工具栏、筛选、管理按钮，保留页头、KPI、甘特。
- `@page` 使用横向、10mm 边距。

## 8. 管理端功能

### 8.1 登录

- 入口：`?admin=1` 的"管理"按钮，或连续点击 logo/标题 5 次。
- 口令输入，SHA-256 哈希比对；连续失败 5 次锁定 30 秒。
- 会话存 `sessionStorage`，关闭标签页失效。
- 登录成功后可加载本机未发布草稿。

### 8.2 任务编辑

- 新增、编辑、删除任务。
- 字段：序号、任务名、责任部门（顿号分隔）、启动时间、完成时间、进度、阶段、备注。
- 进度：0–100 数字输入 + 滑杆 + 快捷按钮（0/25/50/75/100）。
- 日期使用原生 `date` 输入；完成时间早于启动时间时阻止保存。
- 阶段下拉 + 可新建阶段。
- 删除需二次确认。
- 序号"上移/下移"：交换相邻任务序号；在按阶段分组视图中主要影响同日任务顺序，在按序号平铺视图中完整生效。

### 8.3 项目与阶段设置

- 修改项目标题。
- 阶段列表：新增、重命名（同步更新任务）、上移/下移、删除（有任务时需确认并迁移到"未分类"）。
- 查看/生成口令哈希（不自动改线上配置，输出哈希供粘贴到 `config.js`）。
- 丢弃草稿、重置为线上数据。

### 8.4 草稿

- 管理员每次修改后自动写入 `localStorage`（防抖 300ms）。
- 草稿包含：项目 ID、基于的线上版本、保存时间、完整数据。
- 下次登录时若存在草稿：
  - 默认加载草稿，并显示"正在编辑未发布草稿"；
  - 若线上版本已变化，提示草稿基于旧版本，可选择继续或丢弃。
- 非管理员永远只看到线上数据，不加载草稿。
- 发布成功后清除草稿；手动下载后需点"标记为已发布"才清除。

## 9. Excel 导入 / 导出

### 9.1 导入

- 仅管理员可见；支持 `.xlsx`、`.xls`、`.csv`，拖拽或选择文件。
- 使用本地内置 SheetJS 解析，不联网、不使用 CDN。
- 处理规则：
  - 表头识别：忽略前置标题行，按别名匹配列；
  - 日期：Excel 日期、`YYYY-MM-DD`、`YYYY/M/D`、`YYYY.M.D`、`YYYY年M月D日`；
  - 进度：数字或 `30%`；Excel 百分比格式（0.3）自动 ×100；超出 0–100 截断并警告；
  - 完成时间早于启动时间：保留原值并警告；
  - 任务名为空：跳过并警告；
  - 序号缺失：自动编号（优先填补前后序号之间的空位）；
  - 未知阶段：归入"未分类"；
  - 责任部门：按 `、，,；;` 拆分、去重；
  - 重复任务名：允许。
- 导入前展示：任务数、阶段数、前 8 行预览、警告列表。
- 确认后覆盖当前任务与阶段（项目标题不变），写入草稿。
- 只有 0 条有效行时拒绝导入。

### 9.2 导出

- 导出当前全部数据为 `.xlsx`，列顺序与模板一致。
- 附加"填写说明"工作表，写明状态语义、日期格式、部门分隔符。
- 单向导出，用于正式汇报；不自动回写 Excel，避免双轨。

### 9.3 模板

- 提供 `templates/任务分解表模板.xlsx`，含表头、示例行、填写说明。

## 10. 发布机制

### 10.1 发布文件

- 点击"发布"时：
  - 更新 `meta.updatedAt` 为当前时间；
  - `meta.version` +1；
  - 写入发布说明；
  - 生成 `data.js`。
- 发布文件内容：

```js
/* customSchedule data — generated 2026-11-20T23:50:00+08:00 */
window.PROJECT_DATA = { ... };
```

### 10.2 方式 A：手动

1. 下载 `data.js`；
2. 在 GitHub 网页上传/替换仓库根目录的 `data.js` 并提交，或上传到服务器目录；
3. 点击"标记为已发布"清除本地草稿。

### 10.3 方式 B：GitHub 一键发布

- 管理员在设置中填写：
  - `owner`（GitHub 用户名）、`repo`（默认 `customSchedule`）、`branch`（默认 `main`）、`path`（默认 `data.js`）；
  - GitHub **fine-grained token**，权限仅 `Contents: Read and write`，设置有效期。
- 发布时：
  1. `GET /repos/{owner}/{repo}/contents/{path}?ref={branch}` 获取当前文件 SHA；
  2. `PUT` 提交新内容；
  3. 成功后清除草稿，提示 Pages 约 1 分钟内更新。
- 令牌只存管理员浏览器 `localStorage`，不写入 `data.js`、不进仓库、不上传。
- 一键发布需要 https 环境（GitHub Pages、云服务器均可）；`file://` 下不可用。

### 10.4 版本与历史

- 静态页面不自动保留历史；每次下载的 `data.js` 可由管理员自行归档。
- 页面显示最近发布时间与发布说明。

## 12. 技术方案

- 原生 HTML / CSS / JavaScript，无构建步骤、无框架、无 CDN。
- 数据 `data.js` 以 `<script>` 引入，保证 `file://` 双击可打开。
- 甘特图自绘：DOM + CSS Grid + 绝对定位条形，SVG 仅用于图标。
- Excel 读写：本地内置 `vendor/xlsx.full.min.js`（SheetJS，Apache-2.0）。
- 独立 UMD 解析模块 `shared/parse.js`，浏览器与 Node 转换工具共用。
- 日期按本地日历日处理，内部用 UTC 毫秒做日差计算，避免时区偏移。
- 所有用户数据通过 `textContent` 写入 DOM，只有静态模板使用 `innerHTML`，防止 Excel 内容注入。
- 浏览器支持：最新 Chrome / Edge / Safari / Firefox；不支持 IE。

## 15. 风险与限制

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 前端口令不是安全认证 | 懂技术者可绕过 | 明确告知；真正的门槛是发布权限 |
| 公网可见 | 任何拿到链接的人可看 | 不可猜路径、`noindex`、不主动传播；敏感则改内网 |
| GitHub Pages 国内访问不稳定 | 可能出现打不开/慢 | 代码与托管解耦，可原样迁到云服务器或内网 |
| 无变更审计 | 静态方案不保留历史 | 发布说明 + 自行归档 `data.js` |
| Excel 与网页双轨 | 两边都改会产生冲突 | 明确网页为唯一数据源，Excel 只做导入/导出 |
| 浏览器本地草稿丢失 | 清缓存/换设备会丢 | 及时发布；发布文件可归档 |
| SheetJS 体积约 1MB | 首次加载稍慢 | 本地缓存；可接受 |
| 数据源当前为 7 列 | 备注列为空 | 导入器兼容 7/8 列，补列后重新导入 |
